## Design

Components touched: `05_Software/libsigrokdecode/decoders/{nrzi,4b5b,ethernet,
arp,ipv4,udp}` (new, ATK-Logic origin), `02_Tools/upstream/upstreams.lock.toml`
(governance), `02_Tools/build/STATUS.md` (decoder count), two new test files
under `02_Tools/test/`. No change to any existing decoder or the `common`
package.

Provenance (REQ-PLAT-9e71afec): all six ATK-Logic files were byte-identical
in header, decoder id, and directory name to the unmerged upstream PR
sigrokproject/libsigrokdecode#62 (author sam210723) - no ALIENTEK
modification, no id/license/tag drift, all already lowercase/compliant. PR
#62 remains open with review feedback proposing a restructure (merge
ipv4+arp, fold nrzi/4b5b/ethernet into a combined 100base-fx PD) that
contradicts this task's fixed six-decoder chain, so it was not adopted;
ATK's snapshot was taken as-is. No normalization edits were needed - logged
as an inspection finding, not a no-op.

Governance (REQ-PLAT-1fe3f024): libsigrokdecode's lock entry `role` changes
from `"build-dependency"` to `"modified-vendor-tree"` (new label, not
reused pulseview's `"modified-submodule"` - libsigrokdecode was never a git
submodule) with an explanatory comment in the same voice as the libsigrok
removal note. `clone_enabled` was already `false`; unchanged.

Decode evidence (REQ-FUNC-f9a157d9): rejected the demo driver (its canned
patterns do not speak NRZI/4B5B) and real hardware (no 100BASE-FX/TX capture
gear available). Chose a synthesized capture: `gen_networking_stack_captures.py`
builds a real Ethernet II frame (correct FCS, IPv4 header checksum, UDP
checksum, each computed the same way the corresponding decoder validates it)
and encodes it to a raw sample stream with the exact inverse of nrzi/pd.py
and 4b5b/pd.py's own decode state machines, fed to sigrok-cli via
libsigrok's `binary` input module. This is real decode evidence, not a
canned answer key - the decoders derive every reported field from the
encoded bytes themselves. Test seam: `networking_stack_decode_smoke.sh`
asserts on the decoders' own annotation text for both the ARP and the
IPv4/UDP branch of the chain; it is a `*_smoke.sh` file so `run_tests.sh`
picks it up automatically.

Rejected alternative: hand-inspection against the protocol spec (the
fallback the prompt allows) - rejected because the synthesized-capture path
turned out to be fully tractable, and running the real decoders against
real bytes is strictly stronger evidence than reading their source.

No `.agentic/knowledge/` page exists for libsigrokdecode or this decoder
tree; none is owed here.
