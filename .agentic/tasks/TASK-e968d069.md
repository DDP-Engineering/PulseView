## Frame

Problem: A reviewing agent raised eleven build-environment findings; a
verification pass against the working tree confirmed nine, partially confirmed
one, and reclassified one as a provenance fact rather than a defect. The
confirmed defects break the repository's own stated contract: the build
environment is not as repository-contained, prerequisite-checked, or honestly
documented as `02_Tools/build/README.md` and `01_Documentation/Environment_Setup.md`
claim.

Desired outcome: A new Windows developer has one documented route (WSL2 Ubuntu
plus Docker Engine inside WSL2); a native Ubuntu developer can execute the
documented commands from a fresh clone; host prerequisites actually required by
the bootstrap are checked; builder recipe identity reflects the options and
patch bytes that change the image; every build path's network boundary is stated
truthfully; and the archive failure paths are covered by focused tests.

Actors: Windows developer bootstrapping through WSL2; native Ubuntu/Linux
developer; release operator running `build_delivery_set.ps1`; maintainer
regenerating a builder archive.

Primary scenario: developer clones and runs the documented bootstrap ->
`check_host.sh` reports every prerequisite the bootstrap actually needs,
including the manifest-reading Python and the local archive parts ->
`ensure_build_environment.sh` restores or fails closed with an actionable
message -> documented build commands run without a permission or network
surprise the documentation did not predict.

Examples: a fresh native Ubuntu clone runs `bash 02_Tools/bootstrap/check_host.sh`
and is told Python 3.11+ is required before `ensure_build_environment.sh`
tracebacks inside a heredoc; editing `libusb1_upgrade.patch` produces a
different `io.ddp.builder.spec` than the unedited recipe.

Counterexamples: regenerating or republishing the Git LFS archive parts;
building a new dedicated Linux builder image; changing which distribution the
thin Linux tarball links against.

In scope: `builder_spec.sh` identity inputs; Python prerequisite detection and
reporting across `check_host.sh`, `ensure_build_environment.sh` and
`build_image.sh`; digest pinning of the `build_linux.sh` container base;
container-engine selection in `check_host.sh` and `build_linux.sh`; Linux host
check parity for multipart archive availability; documentation corrections in
`Environment_Setup.md`, `02_Tools/build/README.md`,
`02_Tools/build/images/README.md`, `02_Tools/bootstrap/README.md` and
`07_Delivery/toolchain/README.md`; focused tests for the archive failure paths
and for recipe identity; CHANGELOG.

Out of scope: committing, pushing, staging, publication; regenerating or
uploading Git LFS archive parts; a dedicated archived Linux builder image;
per-package apt pinning; a builder-image SBOM or licence inventory; correcting
tracked file modes, which cannot be represented without a Git index operation.

Constraints: STATED - no commit, push, publish, stage, or LFS regeneration
without explicit approval; preserve existing uncommitted working-tree changes;
prefer focused changes over rewrites; do not run multi-hour image rebuilds to
satisfy a unit test. OBSERVED - `.agentic/aegis.toml` runs

## Design

Seven changes, each isolated to the smallest file set that can carry it.

**Identity (REQ-PLAT-e0da0179).** `builder_spec.sh` gains `--qt5-freeze`,
`--glib-version V`, `--skip-patch NAME` (repeatable) and `--no-sigrok-patches`,
mirroring `build_image.sh`. It computes the *requested* patch list - the
candidate list minus skips - rather than the verified-applied list, because it
must stay deterministic without an MXE clone; `build_image.sh` already aborts
when a requested patch does not apply, so requested and applied coincide in
every successful build. The digest input gains one `option=` line per option and
one `patch=<name>=<sha256>` line per selected patch, in the fixed candidate
order. `build_image.sh` and `ensure_build_environment.sh` pass their effective
options through. Rejected: hashing the whole `sigrok-util` patch directory,
which would make unrelated patch files change the mingw identity.

**Python (REQ-PLAT-b78addb8).** A new `02_Tools/build/python_env.sh` exports
`sr_require_python`, which selects the first interpreter that can import
`tomllib` and otherwise fails with the minimum version and the apt command. It
follows the existing `arch_map.sh` precedent of a sourced helper under
`02_Tools/build/` used by both build and bootstrap scripts. `check_host.sh`
reports the same condition as a FAIL row.

**Linux base (REQ-PLAT-4595eeba).** `build_linux.sh` resolves
`builder-base-ubuntu-24.04` from the lock through the same `lock_get` shape
`build_image.sh` uses. A `--print-base` option prints the resolved reference and
exits, giving the test a seam that needs no container. The networked apt step
stays: the thin tarball links against distribution libraries by design, so
removing the network would change which distribution it targets. That is
recorded as a deliberate limitation, not a fix.

**Engine (REQ-PLAT-3a528715).** `build_linux.sh` and `check_host.sh` take
`--engine` and default to `${BUILDER_ENGINE:-docker}`. `check_host.sh` keeps
using `info`, `image inspect` and `run`, which both engines provide; the
docker-specific `{{.DockerRootDir}}` capacity probe falls back to a filesystem
default when the engine does not answer. Documentation states Docker as the
verified engine and Podman as accepted but unverified, which is what
`02_Tools/build/STATUS.md` actually evidences.

**Archive availability (REQ-PLAT-16185e9e).** `check_host.sh` iterates
`07_Delivery/toolchain/*.manifest.toml`, and for each one reports whether its
`part-*` siblings exist and are not Git LFS pointers. Presence and pointer
detection only; the checksum work stays in `ensure_build_environment.sh`.

**Fail-closed tests (REQ-REL-2faf1abc).** No production change. The existing
missing-part, pointer and whole-archive branches gain coverage, including an
assertion that the engine stub never received `load`.

**Documentation (REQ-PLAT-c4b846a8).** Corrections only, plus a new Docker
Engine in WSL2 procedure. Documented invocations move to the
`bash 02_Tools/...` form used already by `build_delivery_set.ps1:115-119`,
because the tracked mode of every `.sh` is 100644 and correcting that needs a
Git index operation this task is not authorised to perform.

Not designed here and reported as deferred: a dedicated archived Linux builder
image, per-package apt pinning, a builder-image SBOM, tracked file-mode
correction, and a PowerShell wrapper test.
